# Roozlet 0.4.1: one calendar shell and live seasonal visuals

Settings, Search and About are persistent native GTK panes in the calendar window. Widget gear, context-menu and CLI settings/search actions present this shell and select its pane. Sidebar, compact-menu and Ctrl+F/Ctrl+K routes converge on the same pane. Repeated activation preserves search input, settings section and scroll state. Escape goes back to Calendar before hiding the shell. Closing the shell leaves the desktop card running. The personal-entry editor remains a separate bounded modal dialog so drafts are not lost.

Preferences reuse the existing grouped controls and responsive section picker. Persian navigation is on the right, with RTL content; English navigation and content are LTR. About includes the bounded Credits and Licenses pages and GitHub links. Long notices wrap and scroll within the shell. Crossfades remain brief, interruptible and disabled by the motion preference or GTK reduced-motion setting; there is no idle animation.

Automatic season maps Jalali months 1–3 to spring, 4–6 to summer, 7–9 to autumn and 10–12 to winter. Artwork and both card marks resolve from the same date/configuration snapshot at draw time, reconciling stale stored scenes. Scenic surfaces do the same. Manual season selection is retained. Follow-viewed-month applies only to calendar/occasion scenery; widget/preferences use today. No annual date/event data or private storage migration is performed.

The supplied winter-image/autumn-accent screenshot could not be reproduced on a fresh 0.4.0 process with automatic-season defaults: actual 20 Mehr 1405 captures already showed autumn artwork and a leaf. Thus 0.4.1 hardens live draw reconciliation without claiming a confirmed original root cause. An upgrade requires closing the old running process; package replacement does not reload already imported Python modules or cached images. Release/install instructions explicitly restart Roozlet and explain automatic versus manual selection.
