# Roozlet 0.4.2 — Reliability and audit fixes

- Malformed annual calendar imports are rejected with an error while bundled data stays available.
- Reminder storage failures are reported. The 24-hour recovery window includes daylight-saving transitions, and future annual entries remain visible in Upcoming.
- Personal markers read occurrence state once per day. A 10,000-entry month lookup fell from 300,000 SQL queries to 30 (6.484 seconds to 0.864 seconds in the recorded check).
- Compact navigation uses usable content width. Navigation and search help scroll on short screens with large text, and retained Settings controls reflect changes made elsewhere.
- Source archives include tracked release files only and exclude symlinks and private database files. Desktop verification tools now match current titles, geometry and embedded pages.

## Install or upgrade

Download the Debian package, source archive and SHA256SUMS into one folder. Verify the checksums, stop the previous process, install and restart:

```sh
sha256sum -c SHA256SUMS
rooz --quit
install -m 644 ./roozlet_0.4.2-1_all.deb /tmp/roozlet_0.4.2-1_all.deb
sudo apt install /tmp/roozlet_0.4.2-1_all.deb
rooz
```

The package and command remain `rooz`. Existing preferences, notes, reminder history and startup choices are preserved. Personal tables remain schema 1; a day index speeds up state lookups. Official calendar data is unchanged: Iranian occasions, holidays and Hijri mapping cover 1405 only.

## Validation and limits

All 93 tests passed at normal and 200% scale: 53 logic/data checks, 34 GTK checks and six notification protocol checks. The extracted package passed headless commands and native window/navigation checks at both scales. Repeated local builds produced identical package bytes, and annual data validation reported no issues. See [the validation record](../TESTING.md).

A real package-manager install/upgrade/removal, login/suspend cycle, physical monitor changes and native pointer/Show Desktop checks were not repeated. Desktop notifications still require Roozlet to be running; service acceptance cannot guarantee popup presentation. No account, telemetry or runtime network dependency was added.
